# Changelog

## XVault 24.0.0 "Aurora" - 2026-11-05

- **A new look, everywhere.** XVault 24 replaces the matte-brass workbench with **Aurora**: an ink-dark ground, an
  iris accent (`#8d7dff`) with a cyan second accent, softer radii, a type scale, a spacing scale and one set of
  motion curves. The dashboard now has a compact **icon rail** instead of the text sidebar, a glassy top bar and lit
  stat tiles. Every page, dialog, menu and the side panel uses the same tokens, so all 16 themes inherit the new
  structure; the classic brass look is still there as the **Graphite** theme, and Paper, True black and the other
  palettes keep their colours.
- **One button system and one icon set.** Every button is built from the same primitives (secondary, primary,
  quiet, danger, icon-only, split, segmented, floating, toolbar) with real hover, press, focus, disabled, loading
  and success/error states (`XVaultUI.busy`). Icons are **Lucide** (ISC), vendored into `xv-icon-set.js` and a
  Remote sprite — no network requests, no emoji glyphs. Icon-only controls get a tooltip and borrow their
  accessible name from it.
- **Library 4.0.** A heading that names what you are looking at (a destination, an author, a tag, a board or a
  saved view) with a plain-language line for the active filters, a **filter builder** (media, posted range or exact dates, author and tag with suggestions, minimum likes, status and kind
  toggles) that writes ordinary search syntax, removable **filter chips** with Clear and Save view, and richer
  cards: avatar, verified badge, reply/thread context, a 1–4 media grid with `+N`, **quoted posts** (hydrated from
  your archive), link cards, polls, Community Notes and your note. Cards, Gallery, Masonry, Compact, Table and
  Timeline were redrawn (Timeline gets an avatar column), facets and the inspector were rebuilt, and selection
  uses a floating bulk bar. Clicking an author, thread or note in a card narrows the search.
- **Phone Remote 3.0.** Rich feed cards (avatar monogram, verified, reply/thread context, media grid, media status,
  quoted post, link card, Later/Note/tags chips, metrics), a **feed / grid** switch that is remembered, a
  bottom-sheet preview with Share (Web Share API, falls back to copying the link), a **Downloads monitor** (live
  progress, stat tiles, transfers and recent files, Pause/Resume/Retry when the device may manage downloads,
  polling only while the view is visible), an **Overview** (archive totals, 12 month bars and top people that open
  as searches, recent activity), and a viewer with swipe, swipe-down to close, double-tap zoom, pinch and pan.
  Aurora, Paper and OLED palettes with matching `theme-color`; skeleton loading; reduced motion respected.
- **Side panel and Command Center.** Lucide action tiles, real switches (`role=switch`), a lit status card, and
  family icons on every palette row.
- **Motion.** View changes, sheets, menus, dialogs and the selection bar move with shared durations and curves;
  everything collapses to instant changes with *Calm motion* or `prefers-reduced-motion`.
- **Fixes:** the command palette showed a mojibake separator (`Â·`) between title and shortcut; muted text on
  raised surfaces was below 4.5:1 contrast (now about 4.9:1); the Library profile test depended on the host
  locale's thousands separator.
- **Compatibility:** archives, recovery files and settings from 23.x load unchanged. The stored theme value
  `graphite` now shows the Aurora palette; pick **Graphite** in Appearance for the classic brass look. The default
  post-text font is now the interface font (Newsreader is still available). The Remote Downloads and Overview views
  need the 24.0 extension and companion (`GET /api/downloads`, `GET /api/overview`, `POST /api/downloads/control`,
  gated by the new `downloads.manage` permission); older companions keep serving Library, viewer and saves.
- Tests: 154 unit tests; a new real-browser Remote test (`tests/remote-aurora-browser.mjs`: feed cards, preview
  sheet, layout persistence, download controls and polling stop, overview jumps, swipe/double-tap/CDP pinch,
  read-only devices, three themes, 320/768/1440 px without overflow, reduced motion, axe-core audits) and CI runs
  every Remote browser test; Python tests for the new companion routes and sanitizers; the axe-core audit covers 28
  dashboard surfaces with 0 serious or critical issues; `scripts/ui-gallery.mjs` renders every layout and page at
  five viewports for screenshots. Live X, a real X-issued archive, Windows/NTFS and screen readers were not tested.

## XVault 23.0.0 "Lodestar" - 2026-11-05

- **The helper works with Firefox.** The FFmpeg helper now pairs with Firefox (its `moz-extension://` UUID) as well as Chrome and Edge, and with several browsers at once (`extension_ids` in `config.json`; `setup_helper.ps1` accepts a comma-separated list). Downloads › Files & health shows the exact pairing ID to paste and, when the helper refuses the browser, what to add. Firefox keeps Native Messaging, so Remote can be registered there (`setup_remote.ps1` accepts a Firefox add-on ID and writes the Mozilla host manifest). The Firefox e2e pairs with the real helper and measures a hard link.
- **Disk & helper panel.** Files & health gets a status panel: helper running / paired / refused, its capabilities, the pairing ID with Copy, how much your downloads take by kind, and **Measure on disk** — the helper walks the folder and counts hard-linked copies once, so the space Link identical copies freed is visible.
- **The helper finishes what it started.** A move interrupted between "link" and "unlink" is completed on the next try instead of being refused forever, and leftover temporary link files are removed at start-up (only when the original still exists).
- **Downloads page, redesigned.** One primary **Pause queue / Resume queue** button, and the pause now survives service-worker and browser restarts (new work waits, running transfers are held). Progress is honest: a percentage only when the server sent sizes, otherwise an indeterminate bar. Live transfers get their own cards (bytes so far, speed, Pause/Resume/Cancel), a two-minute speed history is drawn from real samples, and the history list updates in place with filters (All / Active / Failed / Complete / Waiting — the stat tiles filter too), search, **Retry**, **Show in folder**, **Open source post** and **Copy reason**. Rare actions moved into **More**. The Command Center can pause or resume the queue and jump to failed or in-progress downloads.
- **Fixes:** the Downloads page showed invented progress (35 % while anything downloaded, 8 % while queued) when sizes were unknown; the media probe had no timeout, so a server that stalled could hold a download slot forever (now 12 s); the bandwidth cap could resume a transfer you had paused; hard-linked copies were counted twice in storage totals; an interrupted helper move was refused on every retry; a second, older filter/pause strip on the Downloads page hid rows by text match.
- **Compatibility:** archives, recovery files and settings from 22.x load unchanged. The 22.0 helper keeps working for renames and links; pairing with Firefox, disk usage and recovery need the 23.0 helper (status lists `usage`, `recover`, `firefox`). `config.json` still accepts a single `extension_id`.
- Tests: Python tests for Firefox origins, interrupted-move recovery and disk usage over HTTP; a real-browser Downloads test (`tests/downloads-page-browser.mjs`: real Chromium downloads, a server that sends no size, a 404, persistent pause, resume, retry; in CI); the helper browser test asserts disk usage; the Firefox run gained helper pairing checks (22 checks). Live X, a real X-issued archive, Windows/NTFS and the PowerShell setup changes were not tested.

## XVault 22.0.0 "Keystone" - 2026-11-05

- **Firefox, for real.** The Firefox build was run in a real Firefox (geckodriver + Marionette, `scripts/e2e-firefox.py`, now a CI job) and what broke was fixed: start-up crashed on `chrome.storage.session.setAccessLevel` (missing in Firefox); dashboard messages from `moz-extension://` pages were rejected as foreign; and several tab messages had two listeners answering, so the first (often `null`) reply won. Every tab message now has exactly one owner. Library, capture, downloads to disk, OCR on the event page and automatic backups pass there (19 checks; the live x.com check is opt-in). Still labelled beta.
- **The helper renames and de-duplicates files itself.** With the FFmpeg helper running, Downloads › Files & health gets **Rename N files now** (moves files to the new template, never overwriting, both ends must stay inside the helper's watched folder) and **Link identical copies** (a dry run first; the helper re-checks SHA-256 and replaces extra copies with hard links, so they stop taking space). Records change only for moves the helper confirms. The script download stays as the fallback.
- **Scheduled automatic backups.** System › Storage › Automatic backups writes a recovery file every day, 3 days, week or month into `<media folder>/Backups/` (`xvault-auto-YYYY-MM-DD-HHMM.jsonl`), keeps the newest N, skips the run when nothing changed, and can encrypt (`.xvenc`) with a passphrase kept only for this browser session. The file is built in an offscreen document on Chrome/Edge and in the event page on Firefox; a failed run retries at the next hourly check. Restore is the same as for a manual backup.
- **Library timeline.** A collapsible strip above the results shows how many matching posts fall on each day, week, month or year (chosen from the range), by posting or archiving date. Click a bar or drag across several to narrow the search to those dates (`after:`/`before:`); Bars morph between searches instead of redrawing, the summary previews a drag ("N posts — release to filter"), each filter is a zoom level with **‹ Back** (or `Backspace`) to the previous range, and **All dates** clears it. Keyboard: arrow keys move between bars, `Enter` filters.
- **Thread map in the Reader.** On wide screens a minimap beside the column draws the conversation: the self-thread spine in the first lane, replies stepping right by depth, quotes inside the conversation as dashed links, each row labelled with the handle. It follows your reading position; click a row (or use arrows, `Home`/`End`, `Enter`) to jump there — a hidden reply switches the Reader to *With replies* first. `t` or **Map** toggles it, and the choice is remembered.
- **Motion and notices.** Notices stack (the previous one lifts away), repeat as **×N** instead of flickering, carry a tone (success, error, info), a countdown bar and optional actions such as **Undo**, and the last 30 are in **Recent notices** in the command palette. Segmented controls get a sliding pill that glides to the chosen option; the lightbox zooms out of the thumbnail you clicked; favouriting bursts a few sparks; Atlas, Files and Quality sections glide in as they scroll into view (scroll-driven, transform only). Calm motion turns all of it off.
- **`asof:` shows the past text.** `asof:2024-05-01` now renders each post with the text it had on that day (from the stored revisions) and marks cards that were **edited later**.
- **Year in Review export.** Save a year as a **PNG share card** (totals, month bars, top people, rising topics or achievements; text only, nothing is fetched) or as a **Markdown summary** with the month table, top people, topics and achievements.
- **Fixes:** captures never advanced the library revision (the bump handler was overwritten), so caches, stale checks and "skip unchanged" did not see new captures; helper pairing never succeeded in Chromium (extension GET requests carry no `Origin`, so `GET /bootstrap` was always refused — pairing now uses `POST /bootstrap`); the rename planner with a folder template could move files out of `XVault/`; the instant-actions listener swallowed replies meant for other listeners; 28 top-level Python tests were never run in CI; ESLint warnings are down to 0.
- **Compatibility:** archives, recovery files and settings from 21.x load unchanged. Helper file operations need the 22.0 helper (its status lists the `rename` and `link-duplicates` capabilities); older helpers keep the script fallback. New settings (`autoBackupDays`, `autoBackupKeep`, `autoBackupEncrypt`, `autoBackupSkipUnchanged`) default to off.
- Tests: 150 unit tests (new: timeline buckets, automatic-backup scheduling and retention, capture revision regression on `fake-indexeddb`), Python helper tests for no-overwrite rename, verified hard links and POST bootstrap, real-browser tests for helper file operations (`tests/helper-files-browser.mjs`: real Chromium downloads + real helper process) and automatic backups (`tests/auto-backup-browser.mjs`: offscreen build, encrypted round trip, retention), Library e2e checks for the timeline and Year in Review exports, and the Firefox run. Live X, a real X-issued archive and the helper on Windows/NTFS were not tested.

## XVault 21.0.0 "Forge" - 2026-11-04

- **Archive quality.** Every post gets a 0–100 completeness score from what XVault kept (author, dates, text, engagement, media URLs/sizes/video files, thread info, expanded links, language); under 70 counts as incomplete. A new **Capture › Quality** page shows the score histogram, what is most often missing, and one-click queues: **Repair incomplete posts** (re-opens only those posts), **Fill thread gaps** (parents and quoted posts that are referenced but not archived, following quote chains up to a chosen depth) and an opt-in **Still on X?** check for favourites. All three use one background x.com tab, need an x.com tab you already have open, have daily caps, show progress/ETA, can be paused, resumed or cancelled, survive a worker restart as "interrupted", and keep a history. Search: `quality:<50`, `is:incomplete`/`is:complete`, `has:gap`, `has:missing-quote`; sorts "Most complete" / "Least complete".
- **Change and deletion tracking.** Revisions were already stored; now posts carry change counters and the Reader shows a **word-level diff timeline** of every captured edit (text, poll, link card, Community Note, engagement). When X shows a tombstone or refuses a post page, the post is marked deleted / suspended / protected / withheld / unavailable (only explicit signals count). Search `is:edited`, `edits:>1`, `has:revisions`, `revisions:>2`, `is:deleted`, `is:unavailable`, `is:available`, `is:unchecked`, `status:<state>`; sorts "Recently edited" and "Checked longest ago". On x.com, optional badges mark posts **edited since archived** and **gone from X**, next to the existing "media not downloaded" marker (each can be switched off).
- **Structured post extras.** Capture now keeps polls (choices, counts, end time, final), link cards (title, description, domain, image), Spaces, Community Notes, edit history ids and per-media **alt text**, duration and aspect ratio — all validated at the message boundary. The Reader renders them. Search `has:poll`, `poll:`, `has:card`, `card:`, `has:space`, `has:community-note`, `cnote:`, `has:alt`, `alt:`.
- **Watch lists.** Opt-in per-author or per-search captures on a schedule (every 1–168 h, 1–10 screens each) with a daily cap, a per-list log and "Run now"; matches arrive like any other capture.
- **Link snapshots.** Optional (asks for permission to read websites): readable text and preview metadata of the pages a post links to, fetched without cookies, size-capped, never from x.com/t.co or this computer's local network. Stored as derived data (`xvault-derived` v3), shown in the Reader and searchable with `has:snapshot`.
- **Capture runs.** Presets for bookmarks / likes / profiles / the home timeline (with mirror and resume options), live rate and ETA while a run is going, run history with length and "Run again".
- **X archive import, complete.** Long posts get their full text from `note-tweet.js`; `community-tweet.js` and `deleted-tweets.js` are imported (`source:x-archive-community`, `x-archive-deleted`, with when you deleted them); **media files inside the ZIP are saved as local downloads** instead of being fetched from X again, with the X CDN address as their identity so duplicate checks and verification line up. Direct messages and their media are never read (counted and reported as skipped).
- **Downloads › Files & health.** Per-host health (error types over 14 days, retry backlog, current parallelism), a **duplicate report with Reclaim space** (removes extra copies through Chrome; the kept copy is never touched), **scheduled re-verification** with optional automatic re-download of missing or corrupt files, and **safe renames** to a new filename/folder template: XVault plans the moves (never overwriting, conflicts listed), gives you a macOS/Linux or PowerShell script, and updates its records after you run it.
- **Download policy.** Video quality (highest / ≤1080p / ≤720p / ≤480p), plus **per-rule video quality** in the search language (`source:likes => 720`, first match wins); a download window ("only at night"); holds while Data Saver is on, on a cellular link or a 2G-class connection where the browser reports it; and a bandwidth cap in MB/s. Held downloads stay queued and start on their own.
- **Filename and folder templates** with tokens (`{author}`, `{tweetId}`, `{index}`, `{date}`, `{year}`…`{time}`, `{mediaId}`, `{type}`, `{source}`, `{width}`/`{height}`, `{quality}`, `{text:N}`), a live preview for an image, a video and a GIF, warnings for unknown tokens and names that could collide, and Windows-safe segments.
- **Search 3.0.** Typo tolerance (`telescpe~`), your own synonyms (`ml, machine learning`), diacritic folding (`cafe` finds “café”), **Did you mean** / Allow typos / Search by meaning when a search finds nothing, a tunable **Best match blend** (keywords ↔ meaning) in Settings and next to the sort menu, **search history** with result counts, pins, filtering and day groups (this browser only, can be turned off), and **time travel** — `asof:2024-05-01` shows the vault as it was archived on that day. More filters: `words:`, `chars:`, `duration:>1m`, `res:>=1080` / `res:4k`, `aspect:portrait|landscape|square|wide|tall`, `engagement:>5%`, `weekday:mon|weekend`, `hour:22-6`, `label:blue|any|none`, `link:`, `name:`, `has:link|hashtag|mention|label`. More sorts: date posted (new/old), engagement rate, longest/shortest, quality, recently edited, recently read, most highlights, longest video, highest resolution, last seen, checked longest ago, thread order — and every sort can be saved with a Smart Collection.
- **Multilingual meaning search.** The meaning index folds diacritics, adds Latin spellings of Cyrillic and Greek words (`москва` also indexes `moskva`), and skips stopwords in several languages; an index built by 20.x is rebuilt in the new format the next time it is used.
- **Smart Collections tell you what is new**: a badge counts posts archived since your last visit, for keyword and meaning (`about:`) collections alike.
- **Atlas › Topics.** Automatic topic groups (k-means over the meaning vectors) with distinctive words, size and cohesion; name them (names survive rebuilds), open them as `topic:`/`cluster:` searches, save them as Smart Collections or **make a board** from them (undoable).
- **Router migration finished.** Every message type is now registered with the router (`route(type, handler)`) with an explicit sender policy (content-script actions vs. dashboard-only); the legacy `if (m.type === …)` switch is gone, and unused unsafe types (`GET_ALL`, `GET_LIBRARY_ROWS`, `GET_LIBRARY_CHUNK`, `CLEAR_ALL`) were removed.
- **Firefox.** OCR now has a Firefox path (the engine runs inside the event page when there is no offscreen document), a real crash on start-up (`onConnectNative` is missing in Firefox) is fixed, the manifest declares `data_collection_permissions`, and CI builds the Firefox zip and runs Mozilla's `web-ext lint` (errors fail the build). Still experimental: it has not been run in a real Firefox.
- **Releases** publish the Chrome, Edge and Firefox zips with per-file `.sha256` files and `SHA256SUMS.txt`, lint the Firefox zip, and take the notes from this CHANGELOG section.
- **Fixes:** a Smart Collection without a query no longer gets a stray visit record; a visit queue paused at the very start is no longer resumed by a stale write; replacing an interrupted queue keeps it in the history; the same link is never fetched twice at once; the X archive media count no longer double-counts.
- **Compatibility:** archives, recovery files and settings from 20.x load unchanged. New post fields (`availability`, `poll`, `card`, `space`, `communityNote`, `edit`, media `altText`/`durationMs`/`aspectRatio`, change counters) are optional and validated; counters are backfilled once from the revisions store. Everything new that talks to X or other websites is **off by default**.
- Tests: 140 unit tests (new: v21 search filters and sorts, post extras and tombstones, revision diff, filename templates and rename plans, the generated rename script executed for real, link snapshots incl. local-network blocking, topic clusters, did-you-mean and collection alerts, multilingual tokenising, archive import of notes/community/deleted/ZIP media, the visit queue simulated end to end, IndexedDB behaviour on `fake-indexeddb`, router migration, the Firefox OCR host, Forge settings and download policy); extension and Library e2e and the axe-core audit pass locally. Live X behaviour (capture of the new fields, tombstones, visit and watch queues, badges), a real X-issued archive and a real Firefox were not tested.

## XVault 20.0.0 "Meridian" - 2026-11-04

- **Meaning search.** `about:cooking` finds posts about recipes and dinner even when they never say "cooking", and `similar:<post id>` (or **Find similar** on any post) lists its nearest neighbours. Vectors are learned on-device from your own archive (Random Indexing, `sw/semantic.mjs`): no model download, no network, nothing added to archive records or exports. The index builds in the background without blocking the worker, stays current as posts arrive and can be rebuilt from Storage. A new **Best match** sort orders by meaning score.
- **Search by image.** Choose, paste or drop a picture (or **Find look-alike images** on a post) to find archived images that look like it, using the Duplicate Lab fingerprints.
- **Library 3.0.** Boards (named, coloured, ordered collections with drag-and-drop, counts and `board:` search), a bulk editor (add/remove several tags, add/remove boards, favourite, read later, read state, colour label, note append), **Select by** (same authors or days as the selection, media, video, text-only, untagged, favourites, read later), a right-click/`Shift`+`F10` context menu, an **undo center** (`Ctrl`+`Z` undoes any bulk change from saved snapshots), a sortable **Table** layout and **auto-tag rules** written in the search language (`from:nasa has:video` → tag `space`) with a live preview, apply-to-existing and optional apply-on-capture. Rules only change organisation (tags, favourite, boards, label, read later), never archived content, and re-applying is idempotent.
- **Reader: read later, highlights and progress.** Mark threads for later (`L`) or read (`M`), select text and highlight it (`H`) with an optional note, see reading progress, resume where you stopped, and reaching the end of a Read-later thread marks it read. Search with `is:later`, `is:read`, `is:unread`, `later:true|false`, `has:highlight` and `highlight:<text>`.
- **X data-archive import.** Drop the ZIP from X's "Download an archive of your data" on System → Storage: tweets, likes and bookmarks are read straight from the ZIP in the browser (only the small data files are inflated, so multi-gigabyte archives with media work), shown as a preview, and imported in batches. Anything XVault already captured live keeps its richer data; malformed rows are skipped and counted. Imported posts carry `source:x-archive`, `source:x-archive-like` or `source:x-archive-bookmark`.
- **Encrypted backups.** System → Storage & backups saves the recovery file as a passphrase-protected `.xvenc` file (AES-256-GCM in 1 MiB authenticated frames, PBKDF2-SHA-256 with 600,000 iterations). Reordered, dropped, truncated or tampered data fails to decrypt instead of restoring a shorter archive. Restore accepts `.xvenc` next to `.jsonl`, asks for the passphrase (retry on mistakes) and goes through the existing conflict review.
- **Storage manager.** System → Storage & backups shows browser quota and usage, persistent-storage status (with a request button), per-store record counts, derived-data cleanup (meaning index, look-alike fingerprints, OCR text, activity log trimming), the last backup and the import tools.
- **Adaptive downloads.** The queue backs off when X's media servers answer with server errors, throttling, time-outs or network failures (halving parallelism, at most once per burst) and earns slots back after clean completions; your "parallel downloads" setting stays the ceiling. A live readout on the Downloads page shows the current limit and recent events. Can be turned off in Settings.
- **Atlas Year in Review.** Per-year posted/archived/media/likes totals, top and new people, month-by-month chart with the busiest month and day, **topic drift** (hashtags rising and falling against the previous year), reading and organising totals, 14 achievements, and a **people graph** of who mentions whom among your most archived people (focus a person to light up their connections).
- **Accessibility & customization.** High contrast, always-visible focus rings, a reading-text scale and Reader text size (Settings → Accessibility); every single-key shortcut can be remapped there, and `?` opens a shortcut sheet that reflects the remapping.
- **Cross-browser builds.** `npm run build:all` produces Chrome, Edge and an **experimental** Firefox zip (`scripts/manifest-targets.mjs`): Firefox uses an event page and `sidebar_action`, and loses local OCR, Native Messaging (Remote/FFmpeg helper) and `file:///` access; the build prints every gap.
- **Architecture.** New `sw/router.mjs` gives feature services an explicit message router with per-type sender policy; boards/rules, storage, import, semantic, sync and derived-data messages are routed through it, everything else still falls through to the legacy switch. New engines are pure, unit-tested modules (`sw/semantic.mjs`, `sw/organize.mjs`, `sw/adaptive-concurrency.mjs`, `x-archive-import.mjs`, `backup-crypto.mjs`).
- **Performance.** `npm run bench` measures the engines on synthetic 10k/50k/100k-post vaults. On the development machine: meaning index 0.6 s / 3.2 s / 6.5 s to build (13 MiB at 100k), `about:` queries 6/19/40 ms, `similar:` 3/16/35 ms, search projection 41/215/535 ms, Year in Review insights 0.2/0.5/0.8 s, reading a 20,000-tweet X archive 0.24 s, encrypted backup ~66–130 MiB/s.
- **Compatibility:** archives, settings and recovery files from 19.x load unchanged. New per-post fields (`boards`, `readLater`, `readAt`, `readProgress`, `highlights`) are validated at the storage boundary and travel in recovery files; the meaning index is derived data and can always be rebuilt.
- Tests: 108 unit tests (new: semantic engine, organize/rules, router, adaptive concurrency, manifest targets, X archive ZIP reader incl. deflate/truncation/junk, backup crypto incl. tamper/reorder/truncation, v20 search filters, Year in Review), the extension and Library e2e and the axe-core audit (now also Storage, Year in Review, board manager, rules dialog and a keyboard-only bulk-edit walkthrough) pass locally. Live X capture of the new features, a real X-issued archive ZIP, Firefox at runtime and the Edge store were not tested.

## XVault 19.0.0 "Horizon" - 2026-11-04

- **Duplicate Lab runs in the background.** Look-alike scanning moved into the service worker (`sw/derived-jobs.mjs`): it is checkpointed and resumable (survives closing the dashboard and Chrome restarts via `chrome.alarms`), backs off on X rate limits (429/5xx), marks unavailable images instead of retrying forever, and confirms dHash matches with a DCT perceptual hash. Progress is broadcast live to any open dashboard. Fingerprints live in `xvault-derived` (schema 2) and never leave the computer.
- **Local OCR.** Opt-in "Read text in images" (Settings → Library) reads archived images with a bundled Tesseract engine (`tesseract.js` 7, English model) in an offscreen document. Nothing is downloaded at run time and nothing is uploaded. New search filters: `ocr:word` / `image-text:"phrase"` and `has:ocr`. The manifest gains the `offscreen` permission and `'wasm-unsafe-eval'` for the engine's WebAssembly.
- **Scheduled sync.** Optional Bookmarks/Likes sync (Settings → X.com, off by default) reads only the newest pages in a background x.com tab on a gentle schedule while you are signed in, with run timeouts, failure backoff, Pause/Resume/Run now, and optional notifications for new posts matching watched Smart Collections. Command Center: "Sync bookmarks now", "Sync likes now".
- **Thread-grouped exports.** Export threads as Markdown (one note per conversation plus an index) or as a single offline HTML file, ordered with the Reader's thread logic.
- **Atlas:** calendar and day filters can follow local time or UTC (Atlas Calendar toggle, Settings → Library); `on:`/`before:`/`after:`/`year:` use the same choice. Insights load instantly from the last snapshot and refresh in the background (stale-while-revalidate). The People grid loads progressively as you scroll.
- **Reader:** edit a post's note inline (`N`), fetch a missing parent post from X on request, position indicator, `Home`/`End`/`g`/`G`/`F` navigation, save a thread as standalone HTML, and a phone layout.
- **Search suggestions 2.0:** suggestions are ranked by how often and how recently you use them (stored only in this browser), show a help line with an example for the filter being typed, are grouped (Filters, People, Values, Recent searches, Frequently used), include `ocr:`/`image-text:`/`has:ocr`, open on demand with `Ctrl`+`Space`, support `PageUp`/`PageDown`/`Home`/`End`, and date values follow the calendar time zone.
- **Accessibility:** new `npm run e2e:a11y` (axe-core, WCAG 2.1 A/AA + best practice) audits every dashboard page, the Atlas views, search suggestions, Reader, Command Center and side panel in CI; serious/critical findings fail the build. Fixed every finding: label-in-name on Home tiles and "Select page", the queue filter's accessible name, a keyboard-focusable Integrity log, the calendar's grouping role, contrast of selected archive sources and the Atlas donut, the side panel's language and checkbox labels, and heading order. The audit also checks visible focus, focus return after the Reader and reduced motion.
